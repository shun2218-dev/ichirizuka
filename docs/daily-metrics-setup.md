# 日次のヘルスケア数値をシートに足す（ショートカット + Apps Script）

HealthFit が書き込んでくれるのはワークアウト単位の記録だけです。
安静時心拍数・HRV・体重などの「毎日の状態」は、iPhone のショートカットから
同じスプレッドシートの `Daily` タブに投げます。追加費用はかかりません。

所要時間は 30〜40分。指標を5つに絞った最小構成から始めます。

| 指標 | ヘルスケアでの名前 | 単位 |
| --- | --- | --- |
| 安静時心拍数 | 安静時心拍数 | bpm |
| HRV | 心拍変動 | ms |
| VO2max | 心肺機能 | mL/kg/min |
| 体重 | 体重 | kg |
| 歩数 | 歩数 | 歩 |

睡眠は取り出し方が少し面倒なので、動くようになってから足すのがおすすめです（最後に補足あり）。

---

## Step 1. 受け口を作る（Apps Script・10分）

1. Running タブがあるスプレッドシートを開く
2. **拡張機能 → Apps Script**（このシートに紐づいたスクリプトになります）
3. `コード.gs` の中身を全部消して、`apps-script/daily-metrics.gs` の内容を貼る
4. `TOKEN` の値を自分で決めた長いランダム文字列に書き換える
   （例: パスワードマネージャで32文字生成。**あとでショートカット側にも同じものを入れます**）
5. 保存（⌘S）
6. 右上の **デプロイ → 新しいデプロイ**
   - 種類: **ウェブアプリ**
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
7. 初回は権限の確認が出ます。「詳細」→「（安全ではないページ）に移動」→ 許可
8. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec`）をコピー

> 「アクセスできるユーザー: 全員」は、URL を知っている人がリクエストを送れる状態です。
> だから `TOKEN` が必要になります。URL とトークンは他人に渡さないでください。

**確認:** その URL をブラウザで開いて `{"ok":true,...}` が返れば成功です。

---

## Step 2. ショートカットを作る（20分）

ショートカットアプリ → 新規作成。名前は「Ichirizuka 日次記録」など。

**送るのは「終わった日」だけです。** 実行した当日ぶんは送りません（理由は Step 3）。
そのかわり直近数日ぶんをまとめて送り直すので、1〜2 日実行が飛んでも次の日に埋まります。

構成は次のとおりです。

```
[下限の日付を作る]    4 アクション        … 全指標で共有する
[指標ごとのブロック]  5 アクション × 5 指標 … 検索 →「日付,値」に整形 → POST
```

> **ループでまとめられないか？**
> できません。「ヘルスケアサンプルを検索」の種類は選択式で、変数を差し込めないためです。
> 1 ブロック作ってから複製するのが最短です。

### 2-1. 下限の日付を作る（先頭に 4 アクション）

「4 日前」の日付を文字列で作り、全指標のリクエストに添えます。

1. 「**日付**」→ 現在の日付
2. 「**日付を調整**」→ **4 日**を引く
3. 「**日付を書式設定**」→ 形式: カスタム → `yyyy/MM/dd`
4. 「**変数を設定**」→ 変数名 `from`

**検索フィルタで日を切らない理由。** 「開始日 が次の間」の日付欄には変数を差し込めません。
残るのは「が次の過去の期間内 N 日」ですが、これは実行時刻を起点にした移動窓なので、
範囲のいちばん古い日が途中で切れます。歩数のように 1 日を合計する指標だと、その日に
「途中までの合計」を書き込み、**前に正しく入っていた値を壊します**。

そこで**検索は 1 日広めに取り、実際に書きたい下限を `from` として送ります**。
Apps Script が `from` より前と当日以降を捨てるので、シートに書かれるのは日の境目で
ぴったり切れた 4 日ぶんだけになります。テキストアクションには変数を入れられるので、
こちらは確実に動きます。

**4 日ぶん送る理由。** 前日 1 日だけだと、オートメーションが飛んだ日は永久に欠測します。
同じ日を送り直しても列が上書きされるだけなので、重ねて送る害はありません。
安静時心拍数のように iOS が後から計算して書き込む指標も、これで拾い直せます。

### 2-2. 指標ごとのブロック（5 アクション × 5）

安静時心拍数から作ります。

1. 「**ヘルスケアサンプルを検索**」を追加して、次のように設定する

   | 項目 | 値 |
   | --- | --- |
   | 種類 が次と等しい | **Resting Heart Rate**（安静時心拍数）。既定は `Steps` なのでタップして変える |
   | 開始日 が次の過去の期間内 | **5 日**（`from` より 1 日広く取る。端の切れた日は Apps Script が捨てる） |
   | グループ分け | **なし**（歩数だけ「日」。後述） |
   | 並び順序 | **開始日**。「新しい順」は**オフ**にして古い順にする |
   | 制限 | **オフ**（全件必要なため） |

   アクション名は検索欄に「ヘルスケア」と入れると出てきます（「ヘルスケアサンプルを**記録**」は
   書き込み用なので間違えないこと）。

2. 「**各項目を繰り返す**」を追加し、その中に「**テキスト**」を 1 つ置く

   中身は **変数・カンマ・変数** の 3 つだけです（`[ ]` は入力しません）。

   ```
   [繰り返し項目の開始日],[繰り返し項目の値]
   ```

   - 1 つ目: 変数「**繰り返し項目**」を入れ、タップして **開始日** を選ぶ。さらに
     **日付フォーマット → カスタム → `yyyy/MM/dd`** にする
   - 手で打つのは **`,`（カンマ）1 文字だけ**
   - 2 つ目: 同じく「繰り返し項目」を入れ、**値** を選ぶ

   できあがりは 青いチップ + `,` + 青いチップ という見た目になります。

3. 繰り返しの外に「**テキストを結合**」を追加
   - 入力: 繰り返しの結果
   - 区切り: **カスタム** → **`;`**（JSON の文字列に改行は入れられないため）

4. 「**テキスト**」を追加して、次を丸ごと貼り付ける

   ```
   {"token":"ここにトークン","metric":"resting_hr","from":"[from]","rows":"[結合結果]"}
   ```

   > **`[ ]` は入力しません。** `[from]` を削除して 2-1 の変数 `from` を、`[結合結果]` を削除して
   > 「テキストを結合」の結果を、それぞれ青いチップとして差し込んでください。
   > **その外側の `"` は本物の文字**なので消さないこと。

5. 「**URL の内容を取得**」を追加
   - URL: Step 1 でコピーしたウェブアプリの URL
   - 「詳細を表示」を開く
   - 方法: **POST**
   - 本文を要求: **ファイル**
   - 本文に、直前の **テキスト** を指定
   - （テスト中）直後に「**通知を表示**」を置いて応答を見る

**この 5 アクションを複製**して、残り 4 指標を作ります。変えるのは 4 か所だけです。

| 種類（英語表記） | `metric` | 単位 | グループ分け |
| --- | --- | --- | --- |
| Heart Rate Variability（心拍変動） | `hrv` | ms | なし |
| VO2 Max（心肺機能） | `vo2max` | mL/(kg·min) | なし |
| Weight / Body Mass（体重） | `weight` | **kg**（lb になっていたら必ず変える） | なし |
| Steps（歩数） | `steps` | 歩 | **日** |

**1 日に複数あるサンプルは、いちばん新しい 1 件が残ります。** 古い順に並べてあるので、
同じ日の列を順に上書きしていって最後（＝その日の最新）が残る、という仕組みです。
書き出しファイルからの取り込み（Step 4-A）も同じ採り方なので、混ぜても値がぶれません。

**歩数だけグループ分けを「日」にします。** 1 日に何百件も記録されるため、日ごとに
まとめないと繰り返しが終わりません。まとめた値がその日の合計になります。

> **歩数は 1 回だけ実測と突き合わせてください。** iPhone と Watch が同じ歩数を別々に
> 記録していると二重計上になり、ヘルスケアアプリの表示の倍近くになることがあります。
> 倍近ければ、歩数は Step 4-A の書き出しから入れるほうが正確です
> （あちらはソースごとに合計してから最大のものを採るので二重計上しません）。

### 2-3. 手動で1回実行する

再生ボタンで実行します。初回はヘルスケアへのアクセス許可を聞かれるので許可してください。
指標ごとに次のような応答が返ります。

```
{"ok":true,"metric":"resting_hr","added":4,"updated":0,"skipped":9}
```

`Daily` タブに**前日までの 4 日ぶん**の行ができていれば完成です。
**当日の行はできません**（仕様）。

`skipped` はまとまった数になります。`from` より前（＝検索を 1 日広く取った端の日）と
当日ぶん、それに値が空のサンプルを捨てた数だからです。`added` と `updated` の合計が
4 前後（サンプルのある日数）になっていれば正常です。

実行にかかる時間は十数秒〜30 秒程度です。大半は Apps Script への 5 回の往復で、
繰り返しの回数はあまり効きません。

> **重いとき・件数の警告が出たときは日数を減らしてください。** 2-1 を **2 日**、検索を
> **3 日**に下げれば軽くなります（そのぶん飛んだ日を埋められる余裕は減ります）。

## Step 3. 毎日自動で走らせる

1. ショートカットアプリ下部の **オートメーション** タブ → 右上の **+**
2. **時刻** を選ぶ → **毎日** → **3:00**
3. 「**すぐに実行**」を選ぶ（これを選ばないと毎日確認通知が出ます）
4. 実行するショートカットを指定

**未明に走らせて、前日までを取り込みます。** 夜のうちに当日ぶんを送ると、その時点までの
歩数しか入りません。1 日が完全に終わってから送れば、その日の値は一度で確定します。

- 3:00 なら前日は確実に閉じています。シートに書かれる範囲は `from` と当日の日付で
  決まるので、オートメーションの発火が数分ずれても結果は変わりません
- 安静時心拍数・HRV は睡眠中の値から計算されます。前日ぶんの書き込みが遅れても、
  4 日ぶん送り直しているので次の実行で拾われます
- ダッシュボードの「最新値」は前日の日付になります。当日の値は翌日の未明に入ります

数日動かして安定したら、2-2 の「通知を表示」を削除すると静かになります。

---

## Step 4. 過去の分を取り込む（任意・1回だけ）

毎日の送信は直近数日ぶんだけなので、始める前の記録は入りません。
ヘルスケアには過去のサンプルが残っているので、あとからまとめて流し込めます。

やり方は 2 つあります。**数か月より長い期間なら A を選んでください。**

| | A. 書き出しファイル | B. ショートカット |
| --- | --- | --- |
| 速さ | ファイル 1 つを一括処理。数年分でも数分 | 1 サンプルずつループ。数千件で固まる |
| 件数の上限 | なし | **iOS のプライバシー制限に当たる**（下記） |
| 歩数 | iPhone と Watch の**二重計上を除ける** | 除けない |
| 手間 | 書き出し（数分）+ Mac への転送が要る | iPhone だけで完結 |

> **ショートカットは一度に送れる件数に上限があります。** ヘルスケア由来のデータを
> 「URL の内容を取得」へ大量に流すと、iOS が
> 「このアクションは N 個の "ヘルスケア" 項目を共有しようとしていますが、それは許可されていません」
> と止めます。1 年分（366 日）は止まり、10 日分は通ることを確認しています。
> **数か月を超えるなら A を使ってください。** B で押し切るなら 30 日ずつに分けて実行します。

### A. ヘルスケアの書き出しから取り込む（推奨）

1. iPhone の **ヘルスケア → 右上のプロフィール → すべてのヘルスケアデータを書き出す**
   - 数分かかります。できた `書き出したデータ.zip` を AirDrop などで Mac に送る
2. 解凍すると `apple_health_export/export.xml` があります（数百 MB〜数 GB）
3. まず中身を確認する（シートには何も書きません）

   ```bash
   node scripts/import-health-export.mjs ~/Downloads/apple_health_export/export.xml
   ```

   指標ごとに「何日分・いつからいつまで・最新値」が出ます。
4. 送信先を `.env.local` に 1 回だけ書く

   ```
   SHEET_WEBAPP_URL=https://script.google.com/macros/s/.../exec
   SHEET_WEBAPP_TOKEN=Apps Script の TOKEN と同じ文字列
   ```

   URL は Apps Script の **デプロイ → デプロイを管理** からコピーできます。
   コマンドに直接書くとシェルの履歴に残るので、gitignore 済みの `.env.local` に置きます。
   アプリはこの 2 つを読みません。

5. Daily タブへ送る

   ```bash
   node scripts/import-health-export.mjs ~/Downloads/apple_health_export/export.xml --post
   ```

`--out ./tmp` を付ければ送信せず CSV に書き出すだけにもできます。

スクリプトが気をつけていること:

- **歩数の二重計上**: iPhone と Watch が同じ歩数を別々に記録しているため、単純合計だと
  倍近くになります。ソースごとに合計してから、その日のいちばん多いソースを採ります
- **体重の単位**: `lb` で記録されていれば kg に直します
- **1 日に複数ある指標**（HRV など）: いちばん新しい 1 件。毎日のショートカットと揃えています
- 同じ日を何度送っても列が上書きされるだけなので、やり直せます

### B. ショートカットの期間を広げる

短い期間（数週間程度）なら、Step 2 で作ったショートカットがそのまま使えます。

1. 2-1 の「**日付を調整**」で引く日数を **4 日**から必要な日数に変える（例: 90 日）
2. 各ブロックの検索の「**過去の期間内**」を、その **+1 日**に変える（例: 91 日）
3. 手動で 1 回実行する
4. **終わったら 4 日 / 5 日に戻す**

2 を忘れると検索の範囲が届かず、`from` を広げても古い日は入りません。

1 サンプルずつ繰り返すため、件数が増えると遅くなり、上の**プライバシー制限**にも当たります。
**30 日ずつに分けて、日数を変えながら繰り返し実行**してください。同じ日は列が上書きされる
だけなので、範囲が重なっても害はありません。数か月を超えるなら A のほうが速く、確実です。

- 同じ日の行があれば**その列だけ**上書きします。毎日の送信で入れた値は消えません
- 値が空の日、読めない行、当日以降の行は飛ばします（`skipped` に数が出ます）

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| `{"ok":false,"error":"トークンが一致しません"}` | テキストの `token` とスクリプトの `TOKEN` が違う。前後の空白にも注意 |
| `{"ok":false,"error":"SyntaxError..."}` | テキストの JSON が壊れている。`rows` の前後の `"` を消していないか。「テキストを結合」の区切りが改行のままになっていないか |
| `{"ok":false,"error":"metric が不明です: ..."}` | `metric` の綴りが違う。`resting_hr` / `hrv` / `vo2max` / `weight` / `steps` のどれかにする |
| `added` も `updated` も 0 で `skipped` だけ増える | 繰り返し内のテキストで、日付にフォーマット（`yyyy/MM/dd`）を指定していない。または値プロパティではなくサンプルそのものを入れている。`from` が未来の日付になっていないかも見る |
| 当日の行ができない | **仕様**。1 日が終わってから翌日の未明に入ります |
| 当日の行ができて**しまう** | スクリプトが古い。`apps-script/daily-metrics.gs` を貼り直して**新バージョンで再デプロイ** |
| 古い日の行が入らない | 検索の「過去の期間内」が `from` の日数より狭い。必ず **`from` + 1 日**にする |
| 「N 個の "ヘルスケア" 項目を共有しようとしていますが、それは許可されていません」 | iOS のプライバシー制限。一度に外へ送れる件数を超えている。**日数を減らして分けて実行する**（毎日の 5 日ぶんでは出ません）。過去分の取り込みなら Step 4-A を使う |
| 実行が終わらない・固まる | サンプル件数が多すぎる。2-1 を 2 日、検索を 3 日に下げる |
| HTML が返ってくる | デプロイ設定が「自分のみ」になっている。「全員」で再デプロイ |
| 一部の値が空欄 | その日のサンプルがない。安静時心拍数・HRV は Watch を着けて寝た日だけ記録されます |
| 何も起きない | Apps Script の左メニュー「実行数」でリクエストが届いているか確認 |
| コードを直したのに反映されない | **デプロイ → デプロイを管理 → 鉛筆 → バージョン: 新バージョン** で再デプロイが必要 |

## あとから足せるもの

- **睡眠時間**: タイプ **睡眠** で同じブロックをもう 1 つ作り、**グループ分け: 日**、
  値ではなく **期間** を送る。`sleep_hours` は時間単位なので、繰り返しの中で 3600 で割る
  「計算」を挟む。どの日に付くか（前夜か当日か）はヘルスケアの記録次第なので、
  入れたあと 2〜3 日ぶんを実測と突き合わせること
- **体脂肪率・安静時消費エネルギー**: 同じ形でブロックを増やし、`metric` を変えるだけ。
  `daily-metrics.gs` の `COLUMNS` 末尾に追加すれば列も増えます
- **ラップ・GPS ルート**: HealthFit にすでにある FIT/GPX 書き出し（iCloud か Dropbox 宛の自動化）を使うのが早いです

## ダッシュボードへの取り込み

`Daily` タブに行ができたら、アプリ側に **タブの gid** を教えます。

1. スプレッドシートで `Daily` タブを開き、URL 末尾の `#gid=` の数字をコピー
2. `.env.local`（Vercel なら環境変数）に足す

```
SHEET_DAILY_GID=123456789
```

3. アプリを再起動する（Vercel なら再デプロイ）

これで「コンディション」セクションが出ます。最新値・直近7日平均・前週比のタイルと、
週ごとの安静時心拍数と走行距離を並べたグラフ、日ごとの記録の表が表示されます。

`SHEET_DAILY_GID` を設定しなければセクションは出ません。設定したのに出ない・空の場合は、
セクション内に確認先が表示されます。

| 表示 | 原因 |
| --- | --- |
| セクションが出ない | `SHEET_DAILY_GID` が未設定。または再起動していない |
| 「Daily タブを読み込めませんでした」 | gid が違う、共有設定が閲覧可になっていない |
| 「記録が 1 件もありません」 | gid が Running タブのもの、またはショートカットがまだ動いていない |
| 一部の指標が表から消えている | その指標の値が 1 件も入っていない。脚注に指標名が出るので、ショートカットの `metric` を見直す |
