# FIT の取り込み

HealthFit が書き出す FIT ファイルから、**心拍ゾーンごとの滞在時間**などを取り出して
「Fit」タブへ入れる手順。

## なぜ要るか

Running タブにあるのは「ラン全体の平均心拍」だけで、これでは強度の配分が測れない。

10km を淡々と走った日と、10km の中に 400m × 6 本を入れた日は、**平均心拍がほぼ同じに
なりうる**。トレーニング刺激としては別物なのに、シートの上では区別がつかない。精度が
落ちるのではなく、区別する情報が存在しない。

FIT には心拍ゾーンごとの滞在時間が**計算済みで**入っているので、それを読む。

## 1. HealthFit の書き出し設定

HealthFit → Profile → 書き出し設定で、次の 2 つを確認する。

- **エクスポート先に Google Drive を指定**し、自動エクスポートを有効にする
- **Export Format を `FIT`**（または `FIT and GPX`）にする

1 ワークアウトにつき 1 ファイルが、次の名前で書き出される。

```
2026-07-19-131012-Outdoor Running-<デバイス名>.fit
```

先頭の `YYYY-MM-DD-HHMMSS` はローカル時刻。取り込みはこれを開始日時のキーに使う。

## 2. FIT ファイルを手元に置く

スクリプトはローカルのフォルダを読む。次のどちらかで用意する。

- **Google ドライブ（パソコン版）でフォルダを同期する** — 一度設定すれば以後は自動
- Drive からフォルダをダウンロードする

> Drive API は使っていない。認証の設定を増やさずに済ませるため。

## 3. Apps Script を更新する

`apps-script/daily-metrics.gs` に「Fit」タブへの書き込みを足してある。
スプレッドシート → 拡張機能 → Apps Script を開き、**中身を貼り直して再デプロイする。**

Daily の取り込みと同じエンドポイント・同じ `TOKEN` を使う。新しく作るものはない。

## 4. 取り込む

まず中身を確認する（何も書き込まない）。

```bash
node scripts/import-fit.mjs ~/Google\ ドライブ/HealthFit
```

```
FIT 42 本 / 読めた 42 本

  期間  2026/05/02 07:14:03 〜 2026/08/05 07:41:16
  最新  8420m / 2640秒 / 平均 152bpm / ゾーン 0-41-380-1204-1015-0秒
```

CSV に出して目視したい場合。

```bash
node scripts/import-fit.mjs ~/Google\ ドライブ/HealthFit --out ./tmp/fit.csv
```

問題なければシートへ送る。送信先とトークンは `.env.local` から読む
（コマンドに書くとシェルの履歴に残るため）。

```bash
node scripts/import-fit.mjs ~/Google\ ドライブ/HealthFit --post
```

**同じファイルを二度取り込んでも行は増えない。** 開始日時をキーにした上書きなので、
フォルダ全体を毎回渡してよい。

## 5. アプリから読ませる

「Fit」タブの gid（タブを開いたときの URL 末尾 `#gid=`）を `.env.local` に入れる。

```
SHEET_FIT_GID=123456789
```

**未設定でもダッシュボードは落ちない。** Daily タブと同じ扱いで、設定するまで
その情報を使わないだけ。

## 定期実行について

日々のランを反映するには、走るたびにこのスクリプトを実行する必要がある。

**止まっても気づきにくい**ので、最終取り込み日を画面に出すこと（[#24](https://github.com/shun2218-dev/ichirizuka/issues/24)）。
自動化する場合も、失敗が黙って積み上がらない形にする。

## 取れるもの

| 列 | 中身 |
| --- | --- |
| `Start` | 開始日時。Running タブの行と突き合わせるキー |
| `Moving Sec` / `Distance M` | 動いていた秒数 / 距離 |
| `Avg HR` / `Max HR` | そのランの平均 / 最大心拍 |
| `Zone 0..5 Sec` | **心拍ゾーンごとの滞在秒数** |
| `Zone Bounds` | ゾーンの上限 bpm（例 `97/117/136/155/175/194`） |
| `Max HR Setting` / `Resting HR` | そのとき設定されていた最大心拍 / そのときの安静時心拍 |
| `Laps` / `Lap Trigger` | ラップ数 / ラップの切れかた |
| `RPE` | HealthFit の推定値 |
| `Avg Cadence` | 平均ケイデンス |

**秒単位のデータは入れない。** FIT には 1 秒ごとの心拍・位置・標高も入っているが、
シートに置くと 1 ラン数百行になる。要約だけ入れる。

## 知っておくこと

### ゾーン 0 は「ゾーン 1 より下」

FIT はゾーンを 6 つ持つ。HealthFit の画面に出る Zone 1〜5 の下に、
**下限より下の時間**を入れるバケツがもう 1 つある。

### 最大心拍は実測ではない

`Max HR Setting` は HealthFit の設定値で、既定は年齢式 `211 − 0.64 × 年齢` から出た
推定値。**ゾーンの境界 6 本すべてがこの推定の誤差を共有している。**

実測の心拍がこの値を超えているなら、式が低すぎる証拠になる。

### ラップは構造化練習を意味しない

`Lap Trigger` が `distance` なら、単なる距離オートラップ（1km 刻みなど）で、
インターバルをやったという意味ではない。ラップから練習の構造を読むときはここを見る。

### CRC が合わないファイルがある

HealthFit の書き出しには末尾の CRC が一致しない個体がある。**読める分は使う**方針に
しているので取り込みは止まらないが、件数は警告として出る。急に増えたら書き出し側を疑う。
