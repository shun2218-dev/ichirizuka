# アプリ仕様

「一里塚 / ichirizuka」は、走った記録を積み上げて残りを見るための個人用ダッシュボード。Google スプレッドシートを唯一のデータソースとし、DB を持たない。

## 全体像

```
HealthFit (iPhone) ─→ Running タブ ─┐
                                    │
ショートカット/GAS ─→ Daily タブ  ──┼─→ (CSV) ─→ Next.js ─→ ダッシュボード
                                    │
HealthFit → Drive → FIT → Fit タブ ─┘
          （すべて同じ Google スプレッドシート）
```

書き込み側はアプリの管轄外。アプリは**読み取り専用**。

## データソース

### 取得方法

`gviz` エンドポイントから CSV を取得する。シートを「リンクを知っている全員が閲覧可」にするだけで読める（ウェブ公開は不要）。

```
https://docs.google.com/spreadsheets/d/<SHEET_ID>/gviz/tq?tqx=out:csv&gid=<SHEET_GID>
```

`SHEET_CSV_URL` を指定した場合はそちらを優先する。

取得はサーバーコンポーネント内で行うため CORS は関係しない。キャッシュは 600 秒、タグは Running が `runs`、Daily が `daily`。

Daily タブは `SHEET_DAILY_GID`（または `SHEET_DAILY_CSV_URL`）を設定したときだけ読む。**未設定・読み取り失敗・0 件のいずれでも例外にせず**、ランニングの表示を止めない。

### Running タブの列

ヘッダー名は正規化（空白除去・小文字化）して照合するため、表記揺れを許容する。

| 内部名 | 受け付けるヘッダー | 必須 |
| --- | --- | --- |
| date | `Date` / `日付` | ○ |
| time | `Time` / `開始時刻` | |
| type | `Type` / `種目` | |
| total | `Total Time` | |
| moving | `Moving Time` | |
| elapsed | `Elapsed Time` | |
| distance | `Distance` / `距離` | ○ |
| kcal | `Active Calories` / `Calories` | |
| hr | `Heart Rate` / `心拍数` | |
| elevation | `Elevation Gain` | |
| source | `Source` | |

ヘッダー行は `date` 列を含む最初の行として自動検出する。

### Daily タブの列

`apps-script/daily-metrics.gs` が書き込む列。`date` 以外はすべて欠測しうる。

| 内部名 | 受け付けるヘッダー | 単位 | 必須 |
| --- | --- | --- | --- |
| date | `Date` / `日付` | | ○ |
| restingHr | `Resting HR` / `Resting Heart Rate` / `安静時心拍数` | bpm | |
| hrv | `HRV` / `心拍変動` | ms | |
| vo2max | `VO2max` / `VO2 Max` / `心肺機能` | mL/kg/min | |
| weight | `Weight` / `体重` | kg | |
| steps | `Steps` / `歩数` | 歩 | |
| sleepHours | `Sleep Hours` / `Sleep` / `睡眠時間` | 時間 | |

`Received At` は読まない。指標が 1 つも入っていない行（日付だけの行）はスキップする。

### Fit タブの列

`scripts/import-fit.mjs` が FIT ファイルから作って書き込む列。取り込み手順は
[fit-import-setup.md](fit-import-setup.md) を参照。

**Running タブの平均心拍だけでは強度の配分（80/20）が測れない**ため、ゾーンごとの
滞在時間をここで持つ。同じ距離を淡々と走った日とインターバルを入れた日は平均心拍が
一致しうるので、精度ではなく区別する情報の有無の問題になる。

| 内部名 | ヘッダー | 単位 | 備考 |
| --- | --- | --- | --- |
| start | `Start` / `開始日時` | | Running タブと突き合わせるキー。`yyyy/MM/dd HH:mm:ss` |
| movingSec | `Moving Sec` | 秒 | |
| distanceM | `Distance M` | m | |
| avgHr / maxHr | `Avg HR` / `Max HR` | bpm | そのランの実測 |
| zoneSec | `Zone 0 Sec` 〜 `Zone 5 Sec` | 秒 | **ゾーン 0 は「ゾーン 1 の下限より下」** |
| zoneBounds | `Zone Bounds` | bpm | `97/117/136/155/175/194` の形 |
| maxHrSetting | `Max HR Setting` | bpm | 設定値。既定は年齢式による推定 |
| restingHr | `Resting HR` | bpm | そのランの時点の値 |
| laps / lapTrigger | `Laps` / `Lap Trigger` | | `distance` なら距離オートラップで構造化練習ではない |
| rpe | `RPE` | 1–10 | HealthFit の推定値。自己申告とは別物 |
| avgCadence | `Avg Cadence` | spm | |

ゾーンが 1 つも入っていない行はスキップする（取り込みの目的を果たしていないため）。
**秒単位の記録は入れない。** FIT には 1 秒ごとの心拍・位置・標高もあるが、シートに
置くと 1 ラン数百行になる。

Fit タブは `SHEET_FIT_GID`（または `SHEET_FIT_CSV_URL`）を設定したときだけ読む。
Daily と同じく**未設定・読み取り失敗・0 件のいずれでも例外にしない**。

### パースの方針

| 対象 | 扱い |
| --- | --- |
| 時間 | `0h:44m:44s` / `0:44:44` / `44:44` / 秒数 / シリアル値（1 未満なら 1 日 = 1 とみなす）をすべて受ける |
| 距離 | 全データの**中央値**が 200 を超えていればメートル単位と判定し 1000 で割る。行ごとに判定しない |
| 日付 | 区切りは `/` `.` `-`。年が先（`2026/07/26`）でも後ろ（`07/26/2026`）でも読む。表示形式はシートのロケール任せなので固定しない。2 桁年は判別できないため読めない扱い |
| 時刻 | `HH:MM`。空でも 00:00 として扱う |
| 数値 | 数字・小数点・マイナス以外を除去してから変換。変換できなければ 0 |
| 心拍 | 0 以下なら `null` |
| Daily の指標 | 空欄と 0 以下は `null`（体重 0kg や心拍 0bpm は存在しないため） |

日付が読めない行、距離が 0 の行、時間が 0 の行はスキップする。

結果は開始日時の昇順にソートされる。

## 集計ロジック

### 前処理

`NOISE_KM`（0.4km）未満の記録は誤タップとみなし全集計から除外する。除外件数は脚注に表示する。

### 期間の定義

- **今日**: `wallClockNow()` の 00:00 起点
- **週**: 月曜 00:00 起点
- **直近 7 日 / 28 日**: 今日を含む（明日 00:00 を上限とする）
- **年**: 1 月 1 日から今日まで

タイムゾーンは `APP_TIMEZONE`（既定 `Asia/Tokyo`）。サーバーが UTC でもシートの壁時計とずれないよう、`wallClockNow()` で現在時刻を Asia/Tokyo の壁時計に変換してから比較する。

### 各バケットの集計値

`runs`（本数）/ `km` / `sec` / `kcal` / `elevation` / `pace`（= `sec / km`）/ `hr`（平均、`null` を除外）/ `longest`。

### 負荷指標（ACWR）

```
load = 直近7日の距離 ÷ (直近28日の距離 ÷ 4)
```

直近 28 日が 0 のときは `null`。

| 範囲 | ラベル |
| --- | --- |
| `< 0.8` | 走行量が落ちている |
| `0.8 – 1.3` | 積み上げやすいゾーン |
| `1.3 – 1.5` | 増やしすぎ気味 |
| `> 1.5` | 急に増やしている |

### 強度の配分（80/20）

Fit タブのゾーン滞在時間を 3 つに分ける。80/20 は閾値（LT1 / LT2）で切る 3 ゾーン
モデルの話で、HealthFit の 5 ゾーン（%最大心拍）とは切り方が違うため、割り当て直す。

| 帯 | %最大心拍 |
| --- | --- |
| easy | 80% 未満 |
| moderate | 80–90% |
| hard | 90% 以上 |

**どの帯に入るかは、そのゾーンの上限と下限の中点で決める。** 下限で判定すると設定変更を
またいだときに同じゾーンが別の帯へ落ちる（境界が 195 → 194 に変わると、ゾーン 4 の下限は
`156/195 = 80.0%` と `155/194 = 79.9%` で easy と moderate に割れる）。中点なら両方 moderate。

集計期間は直近 84 日。短すぎると 1 本の練習で数字が跳ねる。週ごとの内訳は走行距離と同じ
月曜起点で 26 週分。

取り込み前のランには FIT が無いため、**期間内のランのうち何本に FIT があるか**を併記する。

### 連続週（streak）

直近から遡って「1 回以上走った週」が何週続いているか。**今週はまだ走っていなくても途切れ扱いにしない**（最新週のみ 0 本を許容する）。

### 日次の指標（コンディション）

Daily タブの各指標について次を出す。指標ごとに欠測日が違うので、日付も指標ごとに持つ。

- **最新値** と その日付（その指標に値が入っている最後の日）
- **直近 7 日平均** と、記録があった日数（`covered`）
- **前週比** = 直近 7 日平均 − その前の 7 日平均。どちらかが欠ければ `null`

未来日の行はシートの打ち間違いとみなして除外する。値が 1 つも入っていない指標は表示から外す。

週ごとの比較用に、走行距離と同じ週の区切り（月曜起点）で安静時心拍数と HRV の週平均も出す。

### 距離帯ごとのベスト

各距離帯で「その距離以上のランのうち最速ペースの 1 本」と該当本数を出す。

距離帯: 3km+ / 5km+ / 10km+ / 15km+ / ハーフ+（21.097km）/ 30km+

上位の距離帯は下位に含まれるため、同じランが複数の距離帯のベストになりうる。

## 画面仕様

単一ページ（`/`）。上から順に:

1. **ヘッダー** — ワードマーク、データ取得時刻、「シートを読み直す」ボタン
2. **ヒーロー** — 今週の距離、本数 / 走行時間 / 平均ペース / 平均心拍、最終ラン からの経過日数、週目標の進捗バー
3. **サイド統計** — 直近 7 日（前週比の増減付き）/ 直近 28 日 / 今年 / 累計
4. **52 週ストリップ** — 棒の高さ = 距離、色 = 平均心拍。破線が週目標。連続週数を併記
5. **今の負荷** — ACWR の値、ラベル、0–2.0 のスケール上のマーカー
6. **強度の配分** — Fit タブがあるときだけ表示（下記）
7. **コンディション** — Daily タブがあるときだけ表示（下記）
8. **距離とペースの関係** — 直近 180 日の散布図。上にあるほど速い
9. **距離帯ごとのベスト** — テーブル
10. **月別** — 直近 12 か月。距離をバーで併記
11. **1 本ずつの記録** — 直近 15 本を表示、残りは `<details>` で折りたたみ
12. **脚注** — 除外件数、データ元、更新のしかた

### 強度の配分のセクション

`SHEET_FIT_GID` が未設定なら**セクションごと出さない**。

1. **3 つのタイル** — easy / moderate / hard の割合（直近 84 日）と、その合計時間
2. **1 本の帯** — 3 つの割合を横に並べたもの。easy 80% の位置に細い縦線
3. **週ごとの推移**（`IntensityStrip`）— 棒の高さがその週の合計時間、色が強度。直近 26 週
4. **脚注** — 期間内のランのうち FIT の記録がある本数、境界が推定値であること

達成度メーターの形にはしない。実測では easy が 1 割程度で、常に「未達」を出すだけの
表示になり情報量がないため。**割合と推移が読めればよい。**

読み取りに失敗した場合と 0 件の場合は、注意書きを**セクション内に**出す。

### コンディションのセクション

`SHEET_DAILY_GID` が未設定なら**セクションごと出さない**。代わりに脚注で設定を促す。

設定済みのときは上から順に:

1. **指標のタイル** — 最新値、その日付、直近 7 日平均と前週比。7 日すべて揃っていない指標は「7 日中 N 日の平均」と明記する
2. **週ごとの推移**（`ConditionChart`）— 上段が週平均の安静時心拍数（折れ線）、下段がその週の走行距離（棒）。直近 26 週
3. **日ごとの記録** — 直近 14 日を表示、残りは `<details>` で折りたたみ
4. 値が入っていない指標があれば、その名前を脚注に出す（ショートカット側の設定漏れに気づけるように）

読み取りに失敗した場合と 0 件の場合は、CSV URL や確認先を添えた注意書きを**セクション内に**出す。ランニングの表示は止めない。

### エラー時

Running のシートが読めない場合、集計を行わず設定手順の案内（`Setup`）を表示する。組み立てた CSV URL を提示し、ブラウザで直接開いて確認できるようにする。

シートは読めたがランの行が 0 件の場合は、`SHEET_GID` の確認を促す。

### 更新

ページは 600 秒キャッシュ。「シートを読み直す」を押すと `POST /api/refresh` が `runs` / `daily` / `fit` のタグを破棄する。シート側の反映ラグは解消しない。

## 環境変数

| 変数 | 必須 | 既定 | 説明 |
| --- | --- | --- | --- |
| `SHEET_ID` | ○ | — | シート URL の `/d/` と `/edit` の間 |
| `SHEET_GID` | ○ | `0` | Running タブの `#gid=` の数字 |
| `SHEET_CSV_URL` | – | — | 指定するとこの URL を直接読む（上 2 つは無視） |
| `SHEET_DAILY_GID` | – | — | Daily タブの `#gid=` の数字。設定するとコンディションを表示する |
| `SHEET_DAILY_CSV_URL` | – | — | Daily タブの CSV URL を直接指定する |
| `SHEET_FIT_GID` | – | — | Fit タブの `#gid=` の数字。FIT の取り込み結果を読む |
| `SHEET_FIT_CSV_URL` | – | — | Fit タブの CSV URL を直接指定する |
| `WEEKLY_TARGET_KM` | – | `30` | 週の目標距離 |
| `APP_TIMEZONE` | – | `Asia/Tokyo` | 日付境界の判定に使う |

`SHEET_ID` は閲覧可能なシートを指すため、実質的にアクセス権に相当する。`.env.example` には書かない。
