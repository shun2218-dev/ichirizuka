# 開発計画

やること・検討中のことを置く。着手が決まったものは Issue を立て、ここからリンクする。

運用ルールは [開発ルール](development-rules.md) を参照。

## 現在の状態

- 単一ページのダッシュボードとして動作
- データソースは Google スプレッドシートの Running タブと Daily タブ（Daily は任意）
- Next.js 16 / React 19、依存は最小限
- テスト・リンター・CI は未導入

## 検討中

Issue 化していない案。着手するときに Issue を立てる。

### データ

- **睡眠データ** — 列と読み取りは用意済み（`Sleep Hours`）。ショートカット側の取り出し方は [daily-metrics-setup.md](daily-metrics-setup.md) の補足を参照
- **体脂肪率・安静時消費エネルギー** — 同じ形で列を増やせる。`daily-metrics.gs` の `COLUMNS` と `lib/sheet.ts` の `Daily` に足す
- **コンディションと走行量の関係を数字にする** — 現在は折れ線と棒を並べて目で見るだけ。相関を出すかどうかは、データが 1 年分たまってから決める

### 画面

- **週の目標距離を UI から変更** — 現在は環境変数 `WEEKLY_TARGET_KM` の再デプロイが必要
- **期間の絞り込み** — 散布図の 180 日、月別の 12 か月が固定
- **レースの目標日を置く** — 「本番までの道のり」を出すなら目標日と逆算が要る

### 基盤

- **テストの導入** — `lib/sheet.ts` のパース（時間の表記ゆれ、距離の単位判定）と `lib/metrics.ts` の期間境界は、壊れても画面を見ないと気づけない。ここだけでも固めたい
- **リンター / フォーマッタ** — `next lint` が Next 16 で削除されたため現在は何も入っていない。ESLint + Prettier を入れるか、Biome 1 本にするか未定
- **CI** — PR で `npm run build` を回す。テスト導入とセットで考える
- **ダークモード** — 色はすべて CSS 変数経由なので `:root` の切り替えで対応できる状態にはなっている

## 保留

対応が必要だが、今は動けないもの。

- **`postcss` / `sharp` の脆弱性（high 3 件）** — `next` の推移的依存。`npm audit fix --force` は `next@9.3.3` へのダウングレードを提案するため適用不可。上流が対応するまで待つ。定期的に `npm audit` で状況を確認する

## やらないこと

方針として採らない選択。蒸し返さないために残す。

- **DB の導入** — シートが唯一の正とする設計。集計は毎回その場で行う
- **チャートライブラリの導入** — SVG を直接書く。バンドルサイズと表現の自由度を優先する
- **書き込み機能** — アプリは読み取り専用。記録の投入は HealthFit とショートカットの担当
- **メニューの消化状況・達成率** — 提案は天候や練習環境で従わないことがある前提なので、
  突き合わせても「守れなかった」を並べるだけになる。走った量は既にヒーローと 52 週ストリップで見える
- **アプリからの通知の送信** — 週次メニューは `/api/plan` を置いて**取りに来てもらう**形にした。
  送信側を持つと通知先の認証情報をアプリが抱えることになる
- **複数ユーザー対応** — 個人用。閲覧を絞るのは Basic 認証（`proxy.ts`）で足りる。
  ログインやセッションを持たない
