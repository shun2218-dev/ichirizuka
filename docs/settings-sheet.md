# Settings タブ

目標タイム・レース日・練習可能曜日を、**再デプロイなしで**変えられるようにするための
シート。

## なぜシートなのか

環境変数に置くと、変えるたびに再デプロイが要る。目標や練習可能曜日は頻繁に見直すものなので
実用にならない。

かといって **UI から書き込む方式は採らない。** [roadmap.md](roadmap.md) の「やらないこと」に
「書き込み機能 — アプリは読み取り専用」と書いてあるとおりで、書き込みを入れると認証と
書き込み権限が必要になり、この設計の前提が崩れる。

**シートを手で編集する。** アプリは読むだけなので、既存の CSV 取得・キャッシュの仕組みが
そのまま使える。「シートを読み直す」ボタンで即反映される。

## 1. タブを作る

スプレッドシート → 拡張機能 → Apps Script を開き、`setupSettingsSheet` を選んで実行する。
`Settings` タブとキーの行が用意される（**値は空のまま**なので自分で埋める）。

手で作ってもよい。1 列目が `key`、2 列目が `value`。**ヘッダー行は無くても動く**
（既知のキーに一致した行だけを拾うため）。3 列目以降は読まないので、メモを書いてよい。

## 2. 値を書く

| key | 例 | 省略したとき |
| --- | --- | --- |
| `goal_marathon_time` | `3:30:00` | 目標の表示が出ない |
| `race_date` | `2027/03/14` | **未定として扱う**（正常） |
| `training_days` | `Tue,Thu,Sat,Sun` | 指定なしとして扱う |
| `weekly_target_km` | `40` | 環境変数 `WEEKLY_TARGET_KM`、それも無ければ 30 |

日本語のキーでも読む（`目標タイム` / `レース日` / `練習可能曜日` / `週の目標距離`）。
曜日は `火・木・土・日` のような書き方も受ける。

**読めない値は既定値に落ちる。** `race_date` に `未定` と書いても落ちず、空と同じ扱いになる。

## 3. アプリから読ませる

`Settings` タブの gid（タブを開いたときの URL 末尾 `#gid=`）を `.env.local` と Vercel に
入れる。

```
SHEET_SETTINGS_GID=123456789
```

**未設定でもダッシュボードは落ちない。** 目標の表示が出ないだけで、走行の記録は今までどおり
見られる。

## 心拍ゾーンと最大心拍はここに置かない

当初はここへ寄せる予定だったが、**FIT がランごとの実際の設定値を持ってくる**ことが分かった
ため不要になった（[fit-import-setup.md](fit-import-setup.md) 参照）。

二重に持つと、HealthFit 側で設定を変えたときに食い違うだけになる。ゾーンの境界は
**そのランを走った時点の値**が FIT に入っているので、そちらが常に正しい。

## レース日が未定でも困らないようにしてある

日程が決まっていなくても練習は続くので、`race_date` が空であることを**正常系として扱う**。
入っていればレースまでの週数を出し、無ければ出さないだけ。

## 週の目標距離の優先順位

```
Settings タブ  →  環境変数 WEEKLY_TARGET_KM  →  30km
```

シートを優先する。環境変数はフォールバックとして残してあるので、Settings タブを作らなくても
今までどおり動く。
